## 3c — DONE (the one-time DV import)

Built as an **assay-side SQL exporter**, NOT an API feed. The "first 3c decision" resolved itself:
the CRUD API can't do this import (`POST` forces a random UUID `id`, `author = session user`,
`status = pending`), whereas §5 needs `id = DV-####`, `author_id = "auto-seeded (provisional)"`,
`status = published` via `INSERT … ON CONFLICT(id) DO UPDATE`. So the import is a **direct D1
seed**: assay emits idempotent SQL, a maintainer applies it.

- **`assay seed-fork-annotations`** (CLI subcommand mirroring `manifest`): reads `loadDvs()` →
  one published, auto-seeded row per DV → idempotent UPSERT SQL.
  - Pure mapping + SQL: `src/catalogue-site/fork-annotation-seed.ts` (`dvsToSeedRows`,
    `buildSeedSql`), tested in `fork-annotation-seed.test.ts` (8 tests).
  - Thin CLI glue: `src/commands/seed-fork-annotations.ts`; wired in `cli.ts`; `--now` /
    `--output` / `--catalogue-dir` flags.
- **Invocation** (maintainer): `node build/cli.js seed-fork-annotations --output
  build/seed-fork-annotations.sql` → `wrangler d1 execute cartularium-assay-preview
  --local|--remote --file=build/seed-fork-annotations.sql`. The `.sql` is generated, not committed.
- **Decisions made (noted, reversible):**
  - **`feature-absent`** — the one off-vocabulary cause (DV-0255, signature `"skip"`) is normalised
