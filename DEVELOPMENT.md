# Development

Local dev runbook for cartularium. For deployment / production concerns, see the deployed-edit-shell docs under `internal/`.

## First-time setup

```bash
# 1. install deps (node 22+, pnpm 10+)
pnpm install

# 2. provision shared dev secrets + worktree symlink
pnpm setup:dev
```

The first `pnpm setup:dev` will print the path of the shared secrets file (`~/.config/cartularium/dev/edit-shell.dev.vars`) and exit. Open that file and fill in your GitHub App credentials:

- `GITHUB_APP_CLIENT_ID` — from the App's settings page
- `GITHUB_APP_CLIENT_SECRET` — same settings page; regenerate if lost
- `GITHUB_APP_PRIVATE_KEY` — paste the `.pem` contents inline, with `\n` escapes (single line)

`ASSAY_RUNNER_TOKEN` is auto-generated by `setup:dev` — leave it alone.

Re-run `pnpm setup:dev` to symlink the worktree's `packages/edit-shell/.dev.vars` to the now-populated shared file.

Sanity check:

```bash
pnpm dev:edit
```

Open `http://localhost:8083/edit/`, sign in. OAuth round-trip should succeed.

## Daily scripts

| Script            | What it runs                                                                                                                        |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm dev`        | Full stack: home (8080), wiki (8081), assay (8082), editor (8083), edit-shell (8787). Use when you need the reader-facing site too. |
| `pnpm dev:edit`   | Editor + edit-shell only. Use for assay workbench, `/edit/*` routes, edit-shell endpoint work.                                      |
| `pnpm dev:runner` | Local hyperformula preview-worker. Run in its own terminal alongside `dev:edit`.                                                    |
| `pnpm setup:dev`  | Refresh shared-secrets symlink. Idempotent.                                                                                         |

`pnpm dev` and `pnpm dev:edit` both auto-apply local D1 migrations first (via `predev` hook).

## Cross-property URLs

Build-time links across the three properties (home / wiki / assay) read three env vars with production defaults:

| Variable                | Default                     |
| ----------------------- | --------------------------- |
| `CARTULARIUM_HOME_URL`  | `https://cartularium.org`   |
| `CARTULARIUM_WIKI_URL`  | `https://sheets.wiki`       |
| `CARTULARIUM_ASSAY_URL` | `https://assay.sheets.wiki` |

`pnpm dev` overrides all three to `http://localhost:808X`. Override individually for one-off tests:

```sh
CARTULARIUM_WIKI_URL=http://staging.example.com pnpm dev
```

Canonical defaults live in [`packages/brand/data/properties.json`](packages/brand/data/properties.json); helpers in [`@cartularium/chrome`](packages/chrome/index.js) (`crossPropertyUrls()`, `urlForHost()`).

## Running preview jobs locally

### Hyperformula (default — works locally)

```bash
# terminal 1
pnpm dev:edit

# terminal 2
export ASSAY_RUNNER_TOKEN=$(grep ^ASSAY_RUNNER_TOKEN ~/.config/cartularium/dev/edit-shell.dev.vars | cut -d= -f2)
pnpm dev:runner
```

In the editor's new-case form, type **`hyperformula`** into the `platforms` field before submitting. The default (`excel, gsheets`) won't be claimed by a hyperformula-only worker.

### Excel / GSheets (tunnel to the volunteer runner)

The volunteer runner on `assay-runner` (host: `chriss.mac.mini.lan`) polls the deployed sheets.wiki. To redirect it at your local stack:

```bash
# 1. Tunnel local wrangler to a public URL
cloudflared tunnel --url http://localhost:8787 > /tmp/tunnel.log 2>&1 &
sleep 5
TUNNEL_URL=$(grep -oE 'https://[a-z0-9-]+\.trycloudflare\.com' /tmp/tunnel.log | head -1)
echo "tunnel: $TUNNEL_URL"

# 2. Redirect the runner (backs up env first)
ssh assay-runner '
  ENV=/Users/assay-runner/cartularium-runner/assay-runner.env
  cp "$ENV" "$ENV.smoke-backup-$(date +%Y%m%d-%H%M%S)"
  sed -i.tmp "s|^ASSAY_RUNNER_BASE_URL=.*|ASSAY_RUNNER_BASE_URL='"$TUNNEL_URL"'/api/edit|" "$ENV"
  rm -f "$ENV.tmp"
  launchctl kickstart -k gui/$(id -u)/wiki.sheets.assay-preview-worker
'
```

You also need to add the runner's bearer to your local `.dev.vars` so wrangler accepts the runner's polls:

```bash
ssh assay-runner 'grep ^ASSAY_RUNNER_TOKEN /Users/assay-runner/cartularium-runner/assay-runner.env'
# copy that value into ~/.config/cartularium/dev/edit-shell.dev.vars (replace
# the auto-generated ASSAY_RUNNER_TOKEN), then restart pnpm dev:edit.
```

When done:

```bash
# revert runner config
ssh assay-runner '
  BACKUP=$(ls -t /Users/assay-runner/cartularium-runner/assay-runner.env.smoke-backup-* | head -1)
  cp "$BACKUP" /Users/assay-runner/cartularium-runner/assay-runner.env
  launchctl kickstart -k gui/$(id -u)/wiki.sheets.assay-preview-worker
'

# kill tunnel
pkill -f "cloudflared tunnel --url http://localhost:8787"
```

**Heads-up:** while pointed at your tunnel, the volunteer runner is NOT processing production jobs. Revert promptly.

## OAuth / GitHub App setup

The local stack uses the same GitHub App as production. You need:

- The App's Client ID, Client Secret, and Private Key (`.pem`).
- The App must have `http://localhost:8083/api/edit/auth/callback` registered as a callback URL (alongside the production callback). If it's missing, add it in the App's settings.

How the local OAuth flow works:

- Editor at `localhost:8083` → user clicks sign in.
- Vite proxies `/api/edit/auth/login` to `localhost:8787` (wrangler) with `X-Forwarded-Host: localhost:8083`.
- Wrangler redirects to GitHub with `redirect_uri=http://localhost:8083/api/edit/auth/callback`.
- GitHub bounces back to localhost:8083 → Vite proxies the callback to wrangler.
- Wrangler exchanges the code for an access token, sets a session cookie with empty `Domain=` (so it scopes to `localhost:8083`), redirects the browser to `/edit/`.

If you see `client_id=undefined` in the GitHub authorize URL, your `.dev.vars` is missing GitHub App credentials — re-check the shared file.

## Multi-worktree usage (today's limitation)

Phase A keeps hardcoded ports. **Only one worktree can run `pnpm dev` (or `dev:edit`) at a time.** Stop the current stack (Ctrl-C) before starting another worktree's.

Phase B (separate PR, planned) will add per-worktree port isolation derived from the worktree path, so concurrent worktree dev becomes possible.

## Known limitations

- **R2 `ASSETS` bucket is remote.** `packages/edit-shell/wrangler.toml` flags only the `ASSETS` bucket (draft image uploads) as `remote = true`, so those writes hit the production R2 bucket from local wrangler. Clean stray dev uploads with:
  ```bash
  pnpm --filter @cartularium/edit-shell exec wrangler r2 object delete cartularium-edit-assets/<key>
  ```
  The `ASSAY_PREVIEW` bucket (preview payloads + results) is local, under `packages/edit-shell/.wrangler/state/v3/r2/` per worktree.
- **Excel / GSheets preview jobs.** No local credential story. Use the tunnel-to-volunteer-runner pattern above.
- **D1 is per worktree.** Schema lives in `.wrangler/state/v3/d1/` per worktree. `predev` runs migrations on each `pnpm dev` so drift is bounded.
- **Wrangler-dev hot-reload of `.dev.vars`.** Wrangler only reads `.dev.vars` at startup. After editing the shared file, restart `pnpm dev:edit`.
